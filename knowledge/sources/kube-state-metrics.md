# kube-state-metrics (KSM) metric catalogue + kubernetes-mixin alert usage

## Provenance

- **KSM docs**: `kubernetes/kube-state-metrics` `main` branch, commit `65f855df9932baa159b3c63fc365a5080b0f7c4d` (2026-09-30), path `docs/metrics/**`. The latest released version in CHANGELOG.md / README is **v2.20.0 (2026-08-16)**. The `main` docs may include metrics added after v2.20.0 but not yet released.
- **kubernetes-mixin**: `kubernetes-monitoring/kubernetes-mixin` `master`, commit `13235f75380f9b651cdc35cc3b050e7e24062ac4` (2026-09-22), `alerts/*.libsonnet` and `rules/apps.libsonnet`.
- Tables are generated by parsing the KSM markdown tables; metric names, types, statuses and labels are copied verbatim.
- **Meaning column**: text without a `*` is the KSM doc description (sometimes shortened). Text ending in `*` means the KSM doc left the description empty, and the meaning was written from the metric name and labels.
- **Status values** are as written in the docs: STABLE, EXPERIMENTAL, ALPHA, plus one typo "EXPIREMENTAL" (`kube_deployment_deletion_timestamp`). The only explicit deprecation is `kube_endpoint_ports`: "STABLE (Deprecated from 2.14.0)". Labels for `kube_node_info` also mark `kubeproxy_version` as `<deprecated>`.
- Enum values are shown inline, e.g. `phase(Pending|Running|...)`, when the doc lists them.
- Common conventions: `*_labels` and `*_annotations` only carry `label_*`/`annotation_*` labels if you set them with `--metric-labels-allowlist` / `--metric-annotations-allowlist`. `*_created` is the unix creation timestamp. Info/condition metrics have value 1 (or 1/0 per condition/status).
- KSM doc notes worth knowing:
  - Pod: kube-scheduler's `kube_pod_resource_request` / `kube_pod_resource_limit` (endpoint `/metrics/resources`) are recommended over `kube_pod_container_resource_requests|limits` because they account for pod-level resources. KSM has no pod-level resources metric.
  - "Terminating" state is not a field. The docs derive it: `count(kube_pod_deletion_timestamp) by (namespace, pod) unless count(kube_pod_status_reason{reason="NodeLost"}) by (namespace, pod)`. They use similar `*_deletion_timestamp * on(...) status_phase{phase="Bound"}` patterns for PV and PVC.
  - `kube_pod_nodeselectors` is opt-in. The `kube_persistentvolume_csi_attributes` description says "disabled by default, manage with --metric-opt-in-list".
  - Custom Resource State (`extend/customresourcestate-metrics.md`) is feature-frozen in favour of resource-state-metrics. VerticalPodAutoscaler metrics were removed from default resources in v2.9.0 and are only available via Custom Resource State config.

## Caveats

- The docs are from `main`, which is at or after v2.20.0. A few rows (ALPHA `*_terminating_replicas`, `kube_pod_resourceclaim_info`, `kube_pod_status_disruption_reason`, PVC VolumeAttributesClass/`Unused`-condition metrics, HPA `*_tolerance`) may be newer than some deployed KSM versions.
- The `lease` resource in KSM docs only has `kube_lease_owner` and `kube_lease_renew_time`.
- Default `--resources` (from `docs/developer/cli-arguments.md` on main) is: certificatesigningrequests, configmaps, cronjobs, daemonsets, deployments, endpointslices, horizontalpodautoscalers, ingresses, jobs, leases, limitranges, mutatingadmissionpolicies, mutatingadmissionpolicybindings, mutatingwebhookconfigurations, namespaces, networkpolicies, nodes, persistentvolumeclaims, persistentvolumes, poddisruptionbudgets, pods, replicasets, replicationcontrollers, resourcequotas, secrets, services, statefulsets, storageclasses, validatingadmissionpolicies, validatingadmissionpolicybindings, validatingwebhookconfigurations, volumeattachments.
  - **Not enabled by default**: `endpoints` (the `kube_endpoint_*` metrics; use `kube_endpointslice_*` instead), `ingressclasses`, `serviceaccounts`, `roles`, `rolebindings`, `clusterroles`, `clusterrolebindings`.
  - `*_labels` and `*_annotations` series only carry label/annotation keys if you set them in the allowlists.
- Many rows have no doc description; those meanings are marked `*` and were written from the metric name and labels.
- Mixin expressions have been lightly condensed: selectors, cluster label and topk dedup wrappers were removed. See the source files for the exact PromQL.
